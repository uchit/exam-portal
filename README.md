# Claude Cert Prep — CCA-F practice portal

A free, open, zero-backend practice portal for the **Claude Certified Architect — Foundations (CCA-F)** exam. 10,000+ questions, timed mock exams, hints, and a full explanation on every answer. Progress is saved in the browser (localStorage) — no login required, so anyone can open the URL and start practicing.

## Exam blueprint (mirrors the official CCA-F)

| Domain | Topic | Weight |
|--------|-------|--------|
| 1 | Agentic Architecture & Orchestration | 27% |
| 2 | Tool Design & MCP Integration | 18% |
| 3 | Claude Code Configuration & Workflows | 20% |
| 4 | Prompt Engineering & Structured Output | 20% |
| 5 | Context Management & Reliability | 15% |

Mock exams use **60 questions / 120 minutes / 72% pass mark**, weighted by the table above — the same shape as the real exam.

## How the question bank is built

Three sources are merged at load time (`js/bank.js`):

1. **Seed questions** — extracted from the official study-guide practice engine (scenario-style "what's wrong with this approach").
2. **Curated questions** — hand-authored architecture-decision questions (`js/curated.js`), matching the exam's scenario style across all five domains.
3. **Generated questions** — a deterministic parametric generator (`js/generator.js`) producing thousands of provably-correct items:
   - **Computed** families (token budgeting, cost, prompt-caching savings, throughput, retry backoff, agent fan-out cost, tool-context growth, few-shot overhead). Each question states its own givens, so the answer is exact and never goes stale; distractors model common mistakes.
   - **Matching** families (API params, MCP concepts, Claude Code features, prompt techniques, stop_reason) — combinatorial concept↔definition pairings.

A seeded PRNG makes the bank identical on every load, so question IDs are stable for progress tracking.

## Certification program

`js/certs.js` is the registry of Anthropic's full 4-track Claude certification
program (CCA-F, CCAR-P, CCAO-F, CCDV-F). Only CCA-F has a live question bank,
curriculum, and study tools today — the other three are tracked there so the
`/certifications` roadmap page stays accurate, and so each new track slots
into the same shape (blueprint → bank → glossary/reference → lessons) once
its content ships, rather than needing a rearchitecture. Don't ship thin
per-track pages ahead of real content — build one track fully, then move on.

## Curriculum

30 lessons (`content/lessons-1.mjs` … `lessons-5.mjs`, 6 per domain) power
`/learn`. Each lesson is `{ slug, title, dek, minutes, bodyHtml }`; `bodyHtml`
is a restricted HTML fragment (`<p> <h2> <h3> <ul> <ol> <li> <strong> <code>
<blockquote> <div class="callout">`) so content stays visually consistent
without a templating engine. Keep new lessons consistent with the
corresponding domain's glossary/reference entries in `scripts/build-pages.mjs`
— they're meant to expand on the same facts, not introduce new ones.

## Pages &amp; routing

The app uses real paths (`/practice`, `/exam`, `/glossary/1`, `/learn/1/…`, …)
via the History API, not hash routing — every page is independently
crawlable. Interactive "app" routes (practice, exam, diagnostic, drill,
browse, progress, prep, home) are rendered client-side by `js/app.js`.
Content pages (about, resources, changelog, glossary, quick reference, blog,
learn, certifications) are static HTML files with real content already baked
in, generated by `scripts/build-pages.mjs`. After editing that script's
content, `js/certs.js`, `content/lessons-*.mjs`, or `js/blueprint.js`'s
domains, regenerate them:

```bash
node scripts/build-pages.mjs
```

`vercel.json`'s `cleanUrls: true` serves `about.html` at `/about`,
`glossary/1.html` at `/glossary/1`, `learn/1/1-1-agentic-loop.html` at
`/learn/1/1-1-agentic-loop`, etc.

## Run locally

```bash
cd exam-portal
python3 -m http.server 8080   # or: npx serve .
# open http://localhost:8080
```

(ES modules require a server — opening `index.html` via `file://` won't work.
`http.server` doesn't emulate Vercel's `cleanUrls`, so content pages need
their `.html` extension locally, e.g. `/about.html` — `vercel dev` gives full
parity if you need to test clean URLs.)

## Deploy

```bash
vercel deploy --prod    # static site, no build step
```
